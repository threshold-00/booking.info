# RealDays marketing site (formerly Threshold)

Static marketing site for RealDays (renamed from Threshold, Ro, 22 Oct 2026), a booking site for small, owner-run experience businesses. The pitch: unique experiences run by the local people who started them, in Victoria, Australia. Free to join, no subscription, no setup fee. No business prices, fees or percentages appear anywhere on the public site (Ro, 14 Nov 2026; see Pricing).

User-facing copy says "RealDays" (capital R and D, no space). The domain is getrealdays.com (Ro, 23 Oct 2026); thresholdbooking.com and www 301-redirect to the same path and query on it through a Cloudflare Redirect Rule, so keep that domain renewed. The repo, file and folder names, CSS/JS identifiers and localStorage keys still say threshold; don't rename those without asking Ro.

**Bali is off the site** (Ro, 14 Nov 2026): the Bali hub, Salty Cowboy's pages and its case study were removed on 15 Nov 2026, with its cards, map pin, the Bali Where option and the Bali map fallback. Don't run `tools/build-salty-cowboy.mjs` (it would rebuild the Bali pages) and don't add Bali back until Ro says so. `data/salty-cowboy.json` stays for history; the private repo's `build-listing-layers.mjs` no longer reads it (15 Nov 2026).

**Only real, active businesses** (Ro, 14 Nov 2026): StudioMade, Elizabeth Peddey and the open listings (Indigo Woodworks, Peachy Keen Ceramics, Suigeneris Atelier, Aysha Hansen, Adventure Flight Co). The demo pages, homepage Demo cards, pins and photos of Gordon Studio, Heathcote Bike Hire, Salty Seas, Spring Creek Horse Rides, Moonraker, Phoenix Pottery, simétrie and East Coast Kayaking were removed on 15 Nov 2026 (Salty Seas photos stay for the design system). Their private data files carry `"taken_down": "2026-11-15"` so the builder never makes them again.

## Deploy

GitHub Pages serves `main` from repo root at **https://getrealdays.com/** (custom domain via `CNAME`). Every page carries a `<link rel="canonical">` to the getrealdays.com URL, Open Graph and Twitter tags, and a JSON-LD block in `<head>`. Remote is `threshold-00/booking.info`. Every push to `main` redeploys automatically, usually within a minute. Never upload files through the GitHub web UI.

## Local preview

```bash
npx browser-sync start --server --files "index.html, styles.css, app.js" --port 3000 --no-notify --no-ghost-mode
```

`--no-ghost-mode` matters: without it browser-sync mirrors clicks between pages. Preview locally first, push only once the change looks right.

## Site specifics

- **Contact form** posts to Formspree when `FORM_ENDPOINT` at the top of `app.js` is set. Falls back to a mail draft to `CONTACT_EMAIL`. The hidden `_gotcha` input is Formspree's spam trap.
- **Prices are Australian dollars only** (Ro, 15 Nov 2026): the currency menu (header and phone menu) is gone, and `ThCurrency.getCurrency()` always returns AUD, ignoring an old saved choice.
- **Contact address** is `CONTACT_EMAIL` in `app.js`, currently `rowena@getrealdays.com`. Hardcoded `mailto:hello@example.com` links are rewritten by `app.js` on load.
- **Experiences section** (`#browse`): a filter nav under the hero (What chips, horse sub-chips, Situation chips Group / Duo / Solo with a one-line helper under them, Where, How long, Sort by, View on map) that sticks under the header once scrolled to, as one 56px row of dropdowns (What, Situation, Where, How long, built by app.js) plus Sort by and View on map (phones: Filters, Sort by, map); then two hand-picked rails ("Good for a first go", "Just added") and "All experiences" (`#browseGrid`). Filters combine with AND; with any filter on, the rails hide. The hero search (What, Where, Situation, Go) sets the same filters. State lives in the URL (`?cat=&sub=&who=&location=&duration=&sort=&map=1`); location, duration and map changes add history entries so the back button steps through them, and the old `view=map` opens the map. Each card carries `data-cat` (the What chips: horse, clay, wood, fashion, flying, food (Elizabeth Peddey, Ro, 7 Nov 2026); only categories with a live business get a chip (Ro, 8 Nov 2026), so sealife, surf and bike come back when one of theirs goes live; Adrenaline went with Tiger Moth World, Ro, 25 Oct 2026), `data-situation` (solo duo group, drafted from group sizes, Ro to confirm) and `data-sort-aud` (price in AUD for Sort by; blank sorts last). Sort options are the `SORT_OPTIONS` list in `app.js`. The Grid / Map tabs are hidden in the markup until Ro decides whether they come back. Duration buckets: 60 min or less, 61 to 300, over 300 on one day, two days or more. Each listed experience has `durationMinutes` (and `durationDays` when it spans 2+ days) in its data file (the private repo's `data/business-layer/<slug>.json` page.experiences, `data/salty-cowboy.json` activities); after changing one or adding a card, run `node tools/card-durations.mjs` to copy them onto the homepage cards (`data-duration`, `data-days`).
- **Last-minute spots rail** (Ro, 15 Nov 2026, brief `docs/briefs/homepage-last-minute-spots-row-2026-11-15.md` in the parent folder): the first rail in `#browseRails` (`#railSpotsSection`), filled by app.js from the booking service's public feed `GET /spots/live.json` (same api switch as the sign-up box). It shows only when at least one spot is live; with none, a failed fetch or no answer in 5 seconds it stays hidden. Cards use the `.sc-card` shell and open each spot's own page on the booking service; "See all" links to the feed's `list_url` when there are more spots than cards. Price line: "$130 per person, usually ~~$170~~". Every value goes in as text, and links and photos must come from the booking service's own address. Like the other rails it hides while a filter is on. Spots stay out of the filters, map pins, `experiences.json`, `sitemap.xml` and `llms.txt`. `SPOT_PILL` puts a "Last minute deal" pill on the photo, only when the business has cut the price (usual price above the spot price), and `SPOT_PLACES_LEFT` shows "3 places left" (the business sets the number): both on (Ro, 15 Nov 2026). Don't remove it because the feed is empty.
- **Map** (`#exploreMap`, inside the "View on map" panel `#mapPanel`: the right half of the screen from 1024px, from under the header to the bottom, with the filter nav and list reflowing into the left half, over the list with a scrim from 768px, full screen on phones) uses vendored Leaflet, built the first time the panel opens, and follows the filters: only pins with a matching card, fitted to the chosen location (All locations fits Victoria; the Bali fallback went with Bali, 15 Nov 2026). ## Default change workflow

1. Make the targeted edit.
2. Preview at http://localhost:3000 and confirm at desktop and under 820px.
3. Show Ro a summary of what changed.
4. If `styles.css`, `app.js` or any shared file in `assets/` (detail.js, demo-booking.js, tokens.css, components.css, booking/) changed, run `node tools/stamp-assets.mjs`. It adds `?v=<hash>` to every reference so browsers fetch the new file instead of a cached one.
5. Commit and push only after Ro approves. Pushing is what publishes the change.
